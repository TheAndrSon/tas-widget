# Как работать с агентом в TAS Widget

## Один раз на задачу

1. Открыть папку `D:\OpenCode_Projects\Widget` как рабочую.
2. Новая сессия.
3. Если задача продолжает вчерашнюю — `/brief`.
4. Сформулировать задачу по шаблону ниже.
5. Подтвердить план.
6. После проверки — `/review` и `/handoff`.

## Шаблон бага

```text
Баг: <что не так, одной фразой>
Виджет: <weather / music / calendar / ...>
Где: UI виджета / настройки / окно и клики
Шаги: 1) ... 2) ... 3) ...
Ожидал: ...
Факт: ...
Не трогать: <соседние виджеты, стили, ...>
Проверка: npm run typecheck && npm run build
```

Если файл известен — указать: `src/renderer/src/widget/widgets/WeatherWidget.tsx`.

## Шаблон доработки

```text
Фича: <что добавить>
Виджет: <тип>
Поведение: <как должно работать>
Настройка: <нужна ли, где в панели>
Ограничения: минимальный diff, без рефакторинга
Проверка: typecheck + build + визуально в npm run dev
```

## Примеры

Плохо:

```text
Почини погоду, она глючит
```

Хорошо:

```text
Баг: при смене города окно погоды прыгает по высоте
Виджет: weather
Где: настройки → город
Шаги: открыть настройки погоды → выбрать другой город → закрыть настройки
Ожидал: размер окна не меняется
Факт: окно становится выше на строку
Не трогать: другие виджеты и стили
Проверка: npm run typecheck && npm run build
```

## Что происходит после запроса

1. Читаю `AGENTS.md` и `widget-dev` (уже загружены).
2. Ищу только нужный виджет через `grep`.
3. Читаю 2–4 файла по цепочке: компонент → настройки → state.
4. Даю план на 3 строки.
5. Делаю минимальный diff.
6. Запускаю `typecheck` и `build`.
7. Отчитываюсь: причина, фикс, проверка.

## Несколько задач подряд

- В той же сессии: просто продолжай. Контекст и предыдущие правки сохранены.
- Новая тема или другой виджет — лучше новая сессия.
- В конце каждой задачи — `/handoff`.

## Что экономит время и токены

- Называть виджет и шаги воспроизведения.
- Указывать файл, если знаешь.
- Не вставлять скриншоты и логи целиком без нужды.
- Не просить «заодно причесать код».
- Не пересказывать проект: он уже в `AGENTS.md`.

## Что делать не нужно

- Открывать `D:\OpenCode_Projects` вместо папки проекта.
- Начинать с «изучи проект».
- Держать один чат на неделю.
- Менять модель посреди задачи.
