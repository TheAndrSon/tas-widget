# TAS Widget: как работать с агентом

## 1. Что это

Десктопные виджеты для Windows: музыка, система, погода, эквалайзер, пламбоб. Отдельное приложение, не связано кодом со старой версией `D:\OpenCode_Projects\Widget`.

## 2. Стек и почему

| Слой     | Технология                     | Почему                                   |
| -------- | ------------------------------ | ---------------------------------------- |
| UI       | React 19 + TypeScript          | быстрый UI, знакомый код старого проекта |
| Оболочка | Electron 45                    | прозрачные окна, трей, WinAPI-трюки      |
| Сборка   | electron-vite 6 + Vite 8       | dev с HMR, простой build                 |
| Хранение | JSON в `%APPDATA%\tas-widgets` | без БД, легко читать и править           |
| Данные   | `systeminformation` + `os`     | локальные метрики без ключей             |

## 3. Запуск

| Действие       | Команда             |
| -------------- | ------------------- |
| установка      | `npm install`       |
| dev            | `npm run dev`       |
| сборка         | `npm run build`     |
| проверка типов | `npm run typecheck` |
| preview        | `npm run start`     |
| тесты          | пока нет            |

## 4. Как ставить задачу

```
Цель: <одно предложение>
Виджет: <system / music / weather / equalizer / plumbob>
Где: <файлы, если известны>
Ограничения: <что не трогать>
Проверка: npm run typecheck && npm run build
```

## 5. Цикл задачи

1. `/brief` — где мы и что дальше.
2. Постановка задачи по шаблону.
3. План (3–7 строк) → подтверждение.
4. Правки минимальным diff.
5. Проверка: `typecheck` + `build`, UI — `npm run dev`.
6. `/review` — ревью diff.
7. `/handoff` — записать состояние.

## 6. Модели

- Драйвер (80% работы): DeepSeek V4.1 Flash.
- Планирование и сложные решения: Kimi K3.1 Pro (plan).
- Разведка по коду: Flash `#low` (explore).
- Ревью: `/review`.

## 7. Когда новая сессия

- Новая тема или новый виджет.
- Сменился слой (main ↔ renderer).
- После завершённой задачи перед следующей.

**Параллельные сессии в одной папке не запускаем:**

- `requestSingleInstanceLock` — второй экземпляр приложения сразу завершится;
- dev-сервер занимает порт 5173;
- общие файлы контракта (`shared/*`, `ipc.ts`, `preload`, `App.tsx`) дадут конфликт правок.

Если параллельность действительно нужна — только через git worktree (отдельная папка) и ручное слияние контрактов. Разведку по старому коду можно делать субагентом параллельно, без правок.

## 8. Чего не делать

- «Изучи весь проект и сделай».
- Один чат на неделю.
- Вставлять большие логи в промпт.
- Менять модель посреди задачи.
- Просить рефакторинг «заодно».
- Копировать весь старый `Widget` целиком.

## 9. Roadmap

Принципы: один виджет за сессию, минимум функций но качественно, приоритет — стабильность и лёгкость.
После каждой сессии: `typecheck` + `build` + `/handoff`.

- [x] **Сессия 0. Каркас.** Окна виджетов, трей, настройки, IPC, системный виджет.
- [x] **Сессия 1. Окно настроек (фундамент).** Отдельное окно, вкладки по виджетам, общие стили и стилевые токены, вкладка «Система». Без него следующие виджеты получат переделку.
- [ ] **Сессия 2. Музыка (SMTC).** Перенос `main/music.ts`, `resources/smtc*.ps1`, `MusicWidget.tsx`. Вкладка настроек. Один экземпляр.
- [ ] **Сессия 3. Погода.** `main/weather.ts` на open-meteo без ключей. **Несколько экземпляров** (несколько городов, как в старом проекте) — здесь меняем модель настроек с `Record<WidgetId>` на список экземпляров.
- [ ] **Сессия 4. Эквалайзер.** Перенос `EqualizerWidget.tsx`, `Visualizer.tsx`, `audio.ts`. Декор рабочего стола, один экземпляр.
- [ ] **Сессия 5. Пламбоб.** Перенос `SimsWidget.tsx` + `shared/sims.ts`, логика экземпляров как в старом проекте (несколько пламбобов), лёгкая доработка.
- [ ] **Сессия 6. Полировка и упаковка.** Общие настройки стиля, portable (`dist:dir`), затем инсталлятор.

### Definition of Done для виджета

1. Данные приходят в UI без ошибок в консоли.
2. Настройки сохраняются и восстанавливаются после перезапуска.
3. `npm run typecheck` и `npm run build` проходят.
4. Проверено в `npm run dev` (данные живые, окно не прыгает).
5. `AGENTS.md` и `.opencode/HANDOFF.md` обновлены.

### Решения по глубине

- Настройки — отдельное окно, вкладка на виджет.
- Мультиэкземпляры — только погода и пламбоб, как в старой версии.
- Визуал вторичен: сначала стабильность и низкий CPU/RAM.
- Публичные API без ключей.
